Part 2: Product Hands-On Teardown — "Track" Flow (Task 1)

Feature Under Analysis: "Track" Flow (Automated Financial Ledger Synchronization)
Objective: Transform raw, noisy, semi-structured SMS and email notification streams into an immutable, audit-ready financial ledger.

2.1 Architecture & End-to-End Ingestion Pipeline

[SMS / Email Notification Received] │ ▼ [On-Device Filter & Noise Rejection] ──(Drop)──► Ignored: Non-Txn (OTPs, Loan Promos, Courier Spam) │ (Settled Bank Alert) ▼ [Multi-Channel Deduplication Engine] ──► Merges SMS + Email alerts for same transaction │ (Correlation Key: {Account} : {MinuteBucket} : {Amount} : {Direction}) ▼ [Regex & Bank-Format Parsers] ────────► HDFC SMS, ICICI SMS V1/V2, Email RFC 1123, E-Mandates │ ▼ [Four-Category Classifier] ────────────► SPEND, INCOME, MICRO (≤ ₹100), TRANSFER (Inter-Account) │ ▼ [Immutable Ledger Store] ──────────────► Amazon DynamoDB Single-Table / SQL Ledger

2.2 Ingestion Edge Cases & Friction Points Identified

Friction Point Real-World Manifestation Engineering Resolution / Architectural Mitigation
Whole-Rupee Regex Trap (INC-2026-09-11) SMS with whole amounts (Rs.5) skips amount regex and erroneously matches the subsequent Avl Bal: Rs.92,213.10. Update amount regex to (?:Rs\.?|INR)\s*([0-9,]+(?:\.[0-9]{2})?) with trailing sentence punctuation lookaheads and strict decimal scaling.
Silent Bank SMS Drops Telecom drop or bank outage causes 1 withdrawal to have no alert (e.g. ₹7,500 gap on Account 4821 in Corpus-A). Detect stated balance jumps between successive messages; isolate and report discrepancies in reconciliation.json.
Multi-Message Redundancy User receives both an SMS and an email for the same UPI debit, inflating ledger row counts. Synthetic correlation key over account, minute-bucket, amount, and direction, merging into one transaction with all source IDs preserved.
Inter-Account Transfers Moving ₹6,000 from HDFC 4821 to ICICI 9075 falsely registers as both ₹6,000 spend and ₹6,000 income. Heuristic matching between known user accounts tags both legs as TRANSFER, cleanly excluding them from net spending metrics.

2.3 Scalable Architecture & Document Store Design

  • Single-Table DynamoDB Partitioning: By partitioning transactions as ACC#<last4>#<YYYY-MM>, monthly statement queries execute with 100% direct efficiency (ScannedCount = Count = 450 at 100k transactions).
  • Atomic Running Totals: Category summaries are updated on a dedicated summary item (SUMMARY#<last4>), converting $O(N)$ table scans into an $O(1)$ single item fetch (ScannedCount = 1, Count = 1).
  • Idempotent Backfill & Deep Consistency Checker: Deduplicates legacy unconstrained rows and verifies field-level data integrity across stores, guaranteeing zero silent corruptions.
